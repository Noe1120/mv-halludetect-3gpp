# 2. 模块插入位置论证分析

> 依据：`要求.md` 第三节第 2 条。
>
> **证据来源**：按要求重新划分的验证集（`seed=3407`，从 3,000 道标准类题目中抽 500 题：Standards specifications 330 题，Standards overview 170 题）。所有探针只读取已有缓存，**没有调用 API，也没有使用 test 集**。答题模型为 deepseek-flash。
>
> **本节为单种子结果，存在随机噪声风险。** 验证集中只有 84 个幻觉样本，AUROC 的 95% 置信区间宽度约为 ±0.06。

## 2.0 先要处理的三处冲突

下面三处是 `要求.md` 与现有工作不一致的地方，需要你确认处理方式。

| 冲突 | 现状 | 建议 |
|---|---|---|
| **评测协议** | 已有的检测结果（AUROC 0.807 等）是在 test 集上做 5 折交叉验证得到的，阈值也在 test 上选。这违反"test 集不能参与调参和选阈值" | 改用新协议：在 seed=3407 的 500 题 val 上训练融合模型、选阈值，在其余 2,500 题 test 上只评测一次。flash 的四个视角已经覆盖全部 3,000 题，**重跑不花 API 费用**。旧结果保留归档，不删除 |
| **硬件** | 要求写的是"纯 CPU、无独显"，但这台电脑有 RTX 4060 8GB，已有的核验耗时是在 GPU 上测的 | 计算继续用 GPU。另外抽 100 题在 CPU 上单独测一遍延迟（ms/query），报告里两种延迟都写 |
| **预算** | DeepSeek 余额只剩 8.61 元，要求的预算是 50 到 200 元 | 需要你充值。下面每个模块都标了预估费用。flash 的实际账单远低于按标价算出的数（有前缀缓存折扣），pro 则接近标价 |

## 2.1 已有基线的缺陷（val 探针）

| 编号 | 探针 | 结果 | 说明的问题 |
|---|---|---|---|
| P0 | 各视角在 val 上的准确率 | 闭卷 78.8%，**BM25 85.2%**，稠密 79.4%，混合+重排 83.2% | 混合检索加重排没有超过 BM25，与 test 上的负面结果方向一致 |
| P1 | NLI 打分 | 所选选项支持度的中位数 0.542；AUROC(1−own) 0.621；AUROC(−margin) 0.585 | NLI 区分能力弱；选项对比特征**反而更差**（选项文本往往是几个词的短语，判断容易被干扰） |
| P2 | Qwen3-0.6B 打分 | 所选选项 P(Yes) 的中位数 0.993；**61% 的题所选选项与最强竞争选项分数相差不到 0.01**；margin 在概率空间的 AUROC 0.681，在 logit 空间 0.705 | 小模型分数接近饱和（"打分虚高"），概率空间的差值被压扁。**换到 logit 尺度后 margin 才有用**，这是特征尺度问题 |
| P3 | 多视角一致性，不训练 | AUROC 0.752；76% 的题四个视角完全一致，其中幻觉率 7.9%；**36% 的幻觉属于"集体犯错"**（所有视角给出同一个错误答案） | 一致性信号强，但有约三分之一的幻觉它天然发现不了 |
| P4 | 检索证据是否覆盖正确选项（AnsHit@5） | 正确样本 49%，幻觉样本 20%；未命中时幻觉率 23.8%，命中时 7.8% | 检索没找到证据是幻觉的主要来源之一 |
| P6 | 生成的解释句长度 | 中位数 26 词，1 句；用规则拆分后子句数中位数为 2，56% 的解释不超过 2 个子句 | 回答很短，**拆原子事实的空间很小** |
| P7 | 纠正的潜力 | 混合 RAG 83.2%；四视角多数投票 83.8%；只要有一个视角答对就算对（oracle 上限）91.4%；单用 BM25 85.2% | 投票纠正只提升 0.6 个百分点；理论上限高，但需要知道该信哪个视角 |
| P8 | LLM-as-a-Judge（缓存 500/500 命中） | AUROC 0.717 | 需要正面比较的强基线 |

## 2.2 各候选模块的插入位置

| 模块 | 插入位置 | 想解决的问题（依据） | 预期收益 | 潜在风险 | 额外开销 | 结论 |
|---|---|---|---|---|---|---|
| 章节切块加上下文前缀 | 检索索引端 | 规范被切碎后丢失所在规范和章节的信息 | 检索命中率提升；文献中 Contextual Retrieval 让检索失败率降 35% 到 49% | 已经实现。固定长度切块的 test 消融没跑完 | 无 API；需要重建索引 | **保留**，补跑 val 上的固定长度切块对照 |
| bge-base 换成 bge-m3 | 检索索引端（稠密） | 稠密检索最弱（P0：79.4%）；bge-m3 支持 8k 长输入 | 稠密视角变好后，混合检索可能跟着变好 | 568M 参数，11.7 万块要重新编码；改变检索结果后，所有 RAG 视角都要重新答题 | 编码在 GPU 上约 20 到 40 分钟；flash 重答 3,000 题的实际账单估计不到 5 元 | **按 `要求.md` 做**，作为单独一轮预注册实验，与 bge-base 对照 |
| RRF 加重排 | 检索融合端 | 单路检索会漏召回 | 已有：AnsHit@5 从 43.0% 提到 46.6%，但答题准确率没有提升（P0） | 重排器偏好语义相似的块，丢掉了 BM25 精确命中的缩写块 | 无 API | **保留现有结果，如实报告为负面结果**；根因诊断见 2.4 |

| 选项对比差值（margin） | 幻觉检测特征端 | 要求中的机制 2 | 只在 logit 尺度上对 SLM 有用（P2：0.705 对比 own 的 0.694），对 NLI 有害（P1） | 分数饱和导致 61% 的题并列；NLI 被短选项干扰 | 无 | **改成 logit 尺度后再做开关实验**；NLI 的 margin 默认关闭 |

## 2.3 选定的插入方案

```
检索索引端：章节切块 + 上下文前缀（已有）→ BM25 ‖ 稠密向量（bge-base；bge-m3 作为单独一轮实验）→ RRF → 重排
生成端：    不改（提示词、temperature、top-k 全部冻结）
检测特征端：[开关] 多视角一致性（核心） + [开关] SLM 核验（logit 尺度 margin） + [开关] NLI 核验
            + [开关] 原子事实核查（规则拆分，在 val 上判定）
后处理端：  [开关] 拒答（主要方式） + [开关] 高风险题改用 BM25 视角的答案（免费的小实验）
评测：      val 上训练融合模型和选阈值，test 上只评测一次；基线 LLM-Judge、SC(K=5)；
            忠实度用本地 NLI 近似 RAGAS；RAGTruth 上只迁移核验器部分
```

## 2.4 已知负面结果的根因（有证据的和需要验证的）

| 现象 | 已有证据 | 推测的根因 | 验证方式（写进 PLAN） |
|---|---|---|---|
| 重排没有让答题准确率提升 | P0；P4 显示证据命中与幻觉强相关 | 3GPP 的缩写和信令名称需要精确匹配，重排器把 BM25 精确命中的块往后排了 | 统计"BM25 前 5 名里有、重排后被挤出前 5 名、并且包含正确选项关键词"的块所占的比例 |
| NLI 的 margin 有害 | P1 | 选项是短短语，"题目+选项"拼出的假设句不通顺，NLI 分数受到干扰 | 按选项长度分组，比较各组的 AUROC |
| SLM 的 margin 在概率尺度上无效 | P2：61% 并列；logit 尺度 0.705 | 分数饱和导致尺度被压扁 | 对比概率尺度和 logit 尺度（已有初步证据，需预注册后复现） |
| 一致性漏掉的幻觉 | P3：36% 是集体犯错 | 闭卷知识和检索证据都偏向同一个错误选项（知识盲区） | 抽 30 个集体犯错的样本人工分类 |
| Qwen3-1.7B 跑到一半报 CUDA 错误 | 第 1,871 题 | 8GB 显存吃紧，加上当时内存不足 | 释放内存后，用 batch=1 重跑剩余的题；或者在 CPU 上跑 |

## 2.6 Telco-RAG 复现可行性（已读源码）

**之前连不上 GitHub 的原因**：Windows 系统代理（127.0.0.1:7897，即 Clash 一类代理工具）当时没开（`ProxyEnable=0`）；DNS 解析结果是 198.18.x.x，说明当时走的是代理软件的 fake-ip 模式，但代理通道没有打通。现在代理已正常工作，github.com 返回 200。

官方仓库 `netop-team/Telco-RAG`（MIT 许可，84 星，最后更新 2024-09-21）已下载到 `D:/claude-home/cache/untrusted/telco-rag/` 并读完源码。论文版本（`Telco-RAG_paper_version/pipeline_offline.py`）的流程是：

1. 用 LLM 把问题改写得更简洁（**1 次 LLM 调用**）；
2. 查 3GPP 词表，把问题中出现的术语和缩写的定义拼接到问题后面（本地完成，用 `3GPP_vocabulary.docx`）；
3. 用 NNRouter（一个小 MLP）根据问题的 embedding 预测相关的 3GPP 系列，取前 5 个；
4. 在这些系列中检索 top-10 块，块长 500 字符，重叠 25 字符；
5. 让 LLM 列出候选答案（**1 次 LLM 调用**），把候选答案拼接到查询里，再预测一次系列并重新检索 top-10；
6. 生成答案（**1 次 LLM 调用**）。

**复现障碍与替代方案**：

| 障碍 | 原因 | 替代方案 |
|---|---|---|
| 嵌入模型是 OpenAI `text-embedding-3-large`（1024 维） | 需要 OpenAI 密钥，而且 NNRouter 和预计算的文档 embedding 都只适配这个模型 | 用本地 bge-m3（也是 1024 维）替换。NNRouter 不能直接复用，改成"用 bge-m3 计算问题与 18 个系列描述的相似度，取前 5 个系列"（原仓库的 `series_description.json` 里有这 18 个系列的描述文本） |
| 答题模型是 gpt-4o-mini | 预算有限，而且应当和本文用同一个答题模型才公平 | 统一用 deepseek-flash |

**结论**：做"**Telco-RAG 风格复现**"（下文记作 Telco-RAG*）。保留它的 4 个核心设计：问题改写、术语表增强、按系列路由、用候选答案二次检索。嵌入模型和答题模型换成与本文相同的，并在论文里写明这些改动。
**成本**：每题 3 次 LLM 调用。在 val 的 500 题上，空闲时段大约 1.5 元（估算方法见 PLAN）。
